# Changelog

## [Unreleased]

### Added

- Approval broker: `velum run` serves a unix socket (`broker.sock` in the run directory, `VELUM_BROKER` in the sandbox, `network.allowUnixSockets` for that one path) where the sandboxed agent asks for `git_push`, `gh`, `open_url` and `run_outside`. A macOS dialog shows the action; approved actions run outside the sandbox. Approvals for a repository are stored in `~/Library/Application Support/velum/approvals.toml` (bound to the push URL; only `<type>/<outcome>` branches without force), requests and decisions are logged in `broker.log`.
- Broker hardening: `git_push` and `gh` work only on the repository recorded at the start of the run whose config and hooks the sandbox cannot write; git runs with the recorded git dir, no hooks, no fsmonitor and `--no-verify`; `gh` runs in the recorded root with `GIT_DIR` and `GIT_WORK_TREE`, and `-S`/`--search` make it a write. Git is pinned to the recorded common directory; a new or changed `commondir`, `config.worktree` or `config`, or a config include of a sandbox-writable file, refuses the repository. `gh` is bound to that repository. `open_url` is asked every time. Requests with control or invisible characters are refused. Connections are served on their own threads with a deadline, one dialog or action at a time (others get "busy"), and running actions and dialogs are killed when the run ends.
- `velum mcp`: stdio MCP server for the broker's tools. `velum run -- claude` passes it to claude with `--mcp-config` (a `mcp.json` in the run directory, read-only for the sandbox), so it exists only inside that run. Nothing is registered with `claude mcp add`. Other programs (such as `claude-agent-acp`) get no config.

## [0.1.0]

### Security

Review fixes:

- Git guard: `hooks` and `config` (and `modules/*/hooks`, `modules/*/config`) of every bare-repository-shaped directory that exists at the start are write-denied. After a run, `core.hooksPath` and `core.fsmonitor` are removed from the config of new repositories (a regular file inside cwd, replaced by rename, never followed through a link) and the warn list gained `alias.*` with `!`, `credential.helper`, `core.gitProxy`, `core.askPass`, `gpg.*.program`, `diff.external`, `diff.*.command`, `merge.*.driver`, `remote.*.uploadpack/receivepack` and `uploadpack.packObjectsHook`. A new `.git` file whose `gitdir:` points outside cwd, through a symlink, or at a repository that existed before is no longer followed (outside or linked targets are reported). `move_aside` copies only regular files after a failed rename; directories and links are listed for removal by hand.
- Version floor: an unreadable `claude --version` (or one that hangs past 10 seconds) now refuses to start claude, with a hint; there is no override.
- Stale run directories are removed only when no process with the pid in the name exists.
- capsa-core: the package manager's `bin -g` query (`pnpm`, `bun`, `npm`) is killed after 10 seconds and treated as unanswered, so `pons self setup` and `doctor` fall back instead of hanging.
- `~/.claude.json`: when the file existed but did not parse as a JSON object (garbage, `[]`), velum used to note it and restore nothing, so a sandboxed claude could add `mcpServers` or `hasTrustDialogAccepted`. Now the pre-run bytes are kept and, if the file differs after the run, written back exactly (atomic rename, no symlink followed) with a warning. The file is never refused, so no data is lost; a concurrent Claude Code edit to such a file is lost, as it could not parse it either.
- `self update` (capsa-core): picks the highest published release of the tool, not the first one GitHub lists; refuses a symlink, hard link, directory or empty file as the binary in the archive; refuses to replace a binary not named after the tool.

Third hardening round (srt 0.0.80, `tests/acceptance.sh`, 36 rows):

- Version floor: `velum run` refuses to start a `claude` older than 2.1.163 (CVE-2026-55607 / GHSA-7835-87q9-rgvv: a worktree named `.git`, symlinks and git's fsmonitor let a repository write `~/.zshenv` and leave Seatbelt), with a hint to run `claude update`. It applies when the program is named `claude` (by path or found on `PATH`); the version is read with `claude --version`, outside the sandbox, with a minimal environment and a 10 second limit. An unreadable version (or a check that takes over 10 seconds) refuses too, with a hint. `velum self doctor` has a `claude version` check: below the floor fails, unreadable warns.
- Bare repositories: after a run, directories under cwd that gained the shape of a bare repository (`HEAD`, `objects/`, `refs/`, outside any `.git`) are reported with a hint to set `git config --global safe.bareRepository explicit`. `velum self doctor` warns when that setting is not `explicit`. velum never edits git config.
- New `deny_write` in cwd and below (`<cwd>/name` and `<cwd>/**/name`): `.gitconfig`, `.vscode`, `.idea`, `.zed` (project settings and tasks run commands), `.zshrc`, `.zshenv`, `.zprofile`, `.zlogin`, `.bashrc`, `.bash_profile` and `.profile`.
- Fail closed, now covered by tests: `velum run` does not start the command when srt is missing, when srt exits at once with an error, when the settings file or the run directory cannot be written, or when claude is below the floor.
- Network: the settings never set `allowLocalBinding` (srt's default is false). Acceptance rows show that `169.254.169.254` and a loopback listener started outside the sandbox are unreachable. `claude.ai` and `platform.claude.com` were already in the default allowlist; nothing was added.

Second hardening round (checked against srt 0.0.80 with `tests/acceptance.sh`):

- Git: the `**/.git/hooks`, `**/.git/config` and `**/.git/modules/*` globs are gone. srt always blocks `.git/hooks` under the working directory and, unless `filesystem.allowGitConfig` is set (velum now sets it), `.git/config`; that broke `git init`. velum denies writes to the `hooks` and `config` of every repository under the working directory by concrete path (also submodule git dirs and `.git` files; bounded walk that skips `target`, `node_modules` and `.build`, caps with a warning and a glob fallback). New repositories are writable; afterwards velum scans for git directories that did not exist before, moves hook files (not `*.sample`) to `~/Library/Application Support/velum/quarantine/<run id>/` and warns about `core.hooksPath`, `core.fsmonitor`, `core.sshCommand`, `core.editor`, `core.pager`, `filter.*`, `diff.*.textconv` and `include*` config entries. `GIT_TEMPLATE_DIR` points to an empty directory so `git init` and `git clone` work; `cargo new` and `cargo init` get `CARGO_CARGO_NEW_VCS=none` (libgit2 cannot write `hooks/README.sample`), so cargo makes no repository: run `git init`.
- Signals: SIGHUP, SIGTERM and SIGINT are forwarded to srt's process group; velum then still restores `~/.claude.json`, scans git and removes the run directory. Processes of the sandbox that outlive srt are killed with a warning. Exit code after a signal is 128 plus its number. Run directories older than a day are removed at the start.
- `~/.claude.json`: besides `mcpServers`, each project's `allowedTools`, `enabledMcpServers`, `disabledMcpServers`, `enabledMcpjsonServers`, `disabledMcpjsonServers`, `hasTrustDialogAccepted`, `hasClaudeMdExternalIncludesApproved` and `mcpContextUris` are guarded. Only keys that changed are put back, merged into the current file (other and concurrent changes stay); the warning lists key and project. Accepting the trust dialog inside a velum run is therefore reverted: accept it outside velum. The file must be a regular file of at most 16 MiB (no symlink, no FIFO, never blocks); after the run a violation is replaced by the pre-run copy through an atomic rename.
- `velum run` refuses a working directory that is or lies inside `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config`, `~/.local`, `~/Library`, `~/.claude`, `~/.cargo` or `~/.rustup`.
- New `deny_write`: `~/.claude/local`, `<cwd>/**/.claude` and `<cwd>/**/.mcp.json`. A relative `**/name` entry is resolved by srt against its own working directory, so it never covers `$HOME`; the anchored form is used.
- Trust: `velum run` refuses when an `allowWrite` entry covers the resolved srt. `velum shim install` refuses when the sandbox could write the real claude or the velum binary; `velum self doctor` (check `trust`) and `shim status` warn.
- `/private/tmp/claude` (the `TMPDIR` srt forces and does not create) and `/private/tmp/velum` are created before every run and by `doctor`, mode 0700, never through a symlink, owned by the user.
- `HOME` that is a symlink: the deny lists hold each `~` entry for the given and the canonical path.
- Env: documented that names with `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `CREDENTIAL` or ending in `_KEY` (`ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`) are dropped even when listed in `env.pass`. New explicit opt-in `[env] pass_secret = ["NAME"]` (exact names). `doctor` lists the secret-looking variables that are set and withheld.

### Changed

- Commands about velum itself are `velum self <action>`: `velum self doctor`, `velum self setup`, `velum self update`, `velum self uninstall`. `doctor` and `setup` are no longer top-level, and there are no aliases. `velum run` and `velum shim` stay top-level.
- `velum self update [--check|--force]` replaces the binary with the newest published `velum-v*` release of LuMiSxh/capsa, after checking the archive against the release's SHA-256; it needs `GITHUB_TOKEN` or `gh auth login`. The new file is written beside the binary, synced and renamed over it, and a symbolic link is resolved to the real binary first. `--check` exits 0 when a newer release exists, 1 when current.
- `velum self uninstall [--dry-run] [--purge] [--dir DIR]` removes the `claude` shim (as `shim uninstall` does; a `claude` that is not velum's shim is left alone), then the binary. The policy file `~/.config/velum/policy.toml` stays unless `--purge`. A binary not named `velum` is refused before anything is removed.
- srt is found on `PATH` and then in the user bin directories (`~/Library/pnpm/bin` among them), by `run`, `doctor` and `setup`. `velum self setup` checks after the install that srt is findable and prints the directory and a hint (`pnpm setup`, or add it to PATH) when it is not on `PATH`.

- `~/.cargo` stays writable, but `~/.cargo/bin`, `~/.cargo/config.toml` and `~/.cargo/config` are `deny_write` (they run code outside the sandbox). The shim now bakes the absolute, canonical path of the velum binary instead of `exec velum`; `shim status` and `doctor` warn when that path is gone or the shim still uses PATH. Reinstall with `velum shim install`.
- The generated srt settings and the swift and xcodebuild wrappers live in a per-run private directory under `~/Library/Application Support/velum/run/` (mode 0700, created exclusively, files mode 0600 or 0700, removed after the child exits). They are no longer in the agent-writable `/private/tmp/velum`, which stays only as `TMPDIR`. velum refuses to run if a write-allowed path covers the run directory. `~/Library/Application Support/velum` is `deny_write`.
- Environment: `CARGO_*` and `RUSTUP_*` are no longer passed by wildcard; the defaults are `CARGO_HOME`, `CARGO_TARGET_DIR`, `CARGO_TERM_COLOR`, `CARGO_INCREMENTAL`, `CARGO_BUILD_JOBS`, `RUSTUP_HOME`, `RUSTUP_TOOLCHAIN`. After the allowlist, any name containing `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD` or `CREDENTIAL`, or ending in `_KEY`, is dropped, as is `CAPSA_HUMAN`, even if a policy wildcard matches. The child's `PATH` loses empty and relative entries.
- New `deny_write`: `~/.claude/settings.local.json`, `~/.claude/commands`, `.claude` and `.mcp.json` in the working directory, `**/.git/modules/*/hooks` and `**/.git/modules/*/config`. `~/.claude.json` stays writable, but velum snapshots its `mcpServers` (top level and per project) and restores them after the child exits, warning on stderr with the names that changed; a file that did not parse as a JSON object is put back byte for byte. An MCP server added with `claude mcp add` inside a velum run is therefore reverted: add it outside velum.
- `velum run` refuses to start in `/`, `$HOME`, an ancestor of `$HOME`, `~/.config/velum`, `~/.local/bin` or `~/Library/Application Support/velum`. `~/.config/velum` and `~/.local/bin` are `deny_write`.
- Policy paths must be absolute without `..` after `~` expansion (deny lists also take `**/name`); `~user` is refused. `HOME` must be absolute and non-empty. Errors are `PolicyError` values with hints.
- `PATH` lookups (`capsa_core::which::find_on_path`, and so srt, claude, swift and xcodebuild) skip empty and relative entries; a wrapper is never written for a relative path.
- Shim refusals carry their fix as a hint, not in the message.

- `velum run`: a policy file that cannot be read or does not parse fails with a hint to run `velum self doctor`; a missing srt fails with a hint to run `velum self setup`. The global `--agent`, `--human` and `--json` flags select the output format.
- `velum self setup`: no change in behaviour; its errors render through the same output formats.
- The `srt` and `claude` lookups and the srt install use `capsa-core` (`which`, `pkg`). A file that is not executable is no longer taken for `srt` or `claude`, and a missing package manager fails with a hint. The default stays pnpm.
- `velum self doctor`: checks srt on PATH and its version, the policy file, the generated srt settings, the first `claude` on PATH (and whether it is the shim), the shim directory's place in PATH, and TMPDIR. `--json` prints an array of `{check, status, detail}`. Exits 1 when a check fails.
- `velum shim install|uninstall|status [--dir DIR] [--dry-run]`: writes a `claude` script that runs Claude Code through `velum run`, with the real claude's path fixed at install time. Install and uninstall touch only files velum wrote.
