# velum agent instructions

Suite-wide rules are in ../AGENTS.md. This file covers velum only.

## Purpose

velum runs a command, normally Claude Code, inside Anthropic's sandbox-runtime (`srt`, npm `@anthropic-ai/sandbox-runtime`, still beta). It merges a layered policy (built-in defaults, then `~/.config/velum/policy.toml`) into an srt settings file, filters the environment, sets `TMPDIR`, and runs `srt -s <settings> -- <cmd>`. Commands about velum itself are `velum self <action>`; `run` and `shim` stay top-level. `velum self setup` installs srt and writes the default policy. `velum self doctor` checks the installation. `velum self update` replaces the binary with the latest release (`capsa_core::update`). `velum self uninstall` removes the shim and the binary, and the policy file only with `--purge`. `velum shim` writes a `claude` shim that runs Claude Code through `velum run`. `PLAN.md` describes the Zed wiring (`pons -- velum claude-agent-acp`), which is not implemented yet.

## Layout

Paths are relative to `velum/`. Neither velum nor pons uses another workspace crate today.

- `src/main.rs`: the `velum` CLI (clap) with `run`, `mcp`, `self` (`setup`, `doctor`, `update`, `uninstall`) and `shim`, and the global `--agent`, `--human` and `--json` flags. `main` returns through `capsa_core::exit::finish`; `run` returns the child's exit code.
- `src/claude_version.rs`: `FLOOR` (Claude Code 2.1.163), `parse`, `verdict` (runs `claude --version`) and `enforce`, which `run` calls for a program named `claude`.
- `src/check.rs`: check results (`Check`, `Status`) rendered as agent lines, a human table or JSON.
- `src/doctor.rs`: the `doctor` checks.
- `src/uninstall.rs`: `velum self uninstall`: the shim, the policy file with `--purge`, then the binary; `TOOL` names this binary for `capsa_core::update`.
- `src/shim/mod.rs`: the `claude` shim: script, install, uninstall, status.

- `src/scratch.rs`: test-only scratch directories.
- `src/policy/`: `Policy` and its parts. `builtin.rs` has the built-in defaults (`Policy::builtin`) and `DEFAULT_POLICY_TOML`; `file.rs` the policy file (`Policy::load`, `from_toml`); `paths.rs` `~` expansion, `check_cwd`, `validate_home` and `default_path`; `mod.rs` `Policy` and the env-name wildcards (`env_matches`); `error.rs` `PolicyError`, which names the file and implements `capsa_core::hint::Hint`. `tests.rs` holds the unit tests.
- `src/srt.rs`: builds the srt settings (`settings`, which validates every fs entry and adds the canonical `HOME` to the deny lists), the filtered environment (`filtered_env`, `passes`, `ENV_DROP`), srt lookup (`find_srt`), the swift and xcodebuild wrappers in `<run dir>/bin`, the git and cargo variables (`install_git_env`), the temporary directories (`prepare_tmp`) and the run itself.
- `src/rundir.rs`: `RunDir`, the per-run private directory (settings, wrappers, git template), removed on drop; `remove_stale` deletes run directories older than a day.
- `src/claude_json/`: `Guard`, which snapshots the guarded keys of `~/.claude.json` and restores the ones that changed after the run (`tests.rs` beside it).
- `src/gitguard/`: `Start`: the repositories under cwd before the run (concrete `deny_write` entries), and the scan after it (quarantine of hooks, report of config entries).
- `src/proc.rs`: the only `unsafe` code: the child's process group, signal forwarding, terminal hand-over, survivor kill, `euid`.
- `src/broker/`: the approval broker. `mod.rs` the socket server (`start`, `Broker`, `approvals_path`, `log_path`); `handler.rs` one request (parse, plan, remember or ask, run, log); `tools.rs` plans for `gh` (`is_read_only`), `open_url` and `run_outside`; `repo.rs` `Recorded`, the repository recorded at the start of the run; `git.rs` the `git_push` plan; `approval.rs` `Approver`, `Gate` and `Memory` (the `approvals.toml` store); `dialog.rs` the `osascript` approver and the dialog text; `exec.rs` `Executor`, the git-safe environment, the 10 minute limit, the 20 KB cut and `Registry` (running process groups, killed at the end of the run); `request.rs` the wire types and `Refusal`; `text.rs` `forbidden`, `clean` and argument quoting; `log.rs` `broker.log`. `tests.rs` uses a fake approver and executor.
- `src/mcp/`: `velum mcp`, the stdio MCP server (`serve`) that forwards `tools/call` to `$VELUM_BROKER` (`tests.rs` beside it).
- `src/safedir.rs`: `ensure_private_dir`: a directory made without following links, owned by the user.
- `src/writable.rs`: judges from the srt settings whether a path is writable (`allowed_by`, `writable_by`, `ensure_not_writable`).
- `src/setup.rs`: `velum self setup`: writes the default policy if it is missing, then installs srt with pnpm, npm or bun (`capsa_core::pkg`) unless `find_srt` already finds it, and checks afterwards that it is findable.
- `tests/fail_closed.rs`: runs the built `velum run` with fake srt and claude programs and proves that the command never starts when srt is missing or fails, when the run directory cannot be made, or when claude is below the floor.
- `tests/acceptance.sh`: checks against the real srt, one row per spike check in the "Spike results" section of the root `PLAN.md`.

## Commands

- `cargo test -p velum`: unit tests in each module, including the shim round trip through `sh`.
- `cargo run -p velum -- run --dry-run -- <cmd>`: prints the srt settings and the names of the passed environment variables, then exits without running `<cmd>`.
- `cargo run -p velum -- self setup --dry-run`: prints what would be written or installed.
- `cargo run -p velum -- self update --check`: reports whether a newer release exists (needs `GITHUB_TOKEN` or `gh auth login`). `self uninstall --dry-run [--purge] [--dir DIR]` prints what would be removed; test the real removal only on a copy of the binary under a temporary `HOME` (`tests/self_uninstall.rs`).
- `cargo run -p velum -- self doctor`: prints each check; `--json` (or `--agent`/`--human`) picks the format. Exits 1 when a check fails.
- `cargo run -p velum -- shim install --dry-run`: prints the shim script and its path. `shim uninstall` and `shim status` take `--dir DIR`; `uninstall` takes `--dry-run`.
- `sh velum/tests/acceptance.sh`: exit 0 when every row passes, 1 when one fails, 77 when srt is missing (skipped). It needs a real srt to mean anything. If `CARGO_TARGET_DIR` is set, it must be absolute.

## Contracts

- Policy file format: `[fs]` with `write`, `deny_read` and `deny_write`; `[env]` with `pass` and `pass_secret`; `[net]` with `allow`. The file is `~/.config/velum/policy.toml` unless `run --policy` names another. It extends the built-in defaults and never removes them. The generated file from `self setup` comments every entry out, so it changes nothing.
- Defaults grow only with the user's explicit approval. This is security-sensitive (root rule): changes to `Policy::builtin` need tests and a review before they are committed.
- The generated srt settings always contain `network.deniedDomains`, even when empty, because srt requires it.
- Env: the built-in `env.pass` lists exact names (no `CARGO_*`/`RUSTUP_*` wildcard); policy files may add wildcards. `passes` removes `CAPSA_HUMAN` and any name containing `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD` or `CREDENTIAL` or ending in `_KEY` (so `ANTHROPIC_API_KEY` and `CLAUDE_CODE_OAUTH_TOKEN`), even when `env.pass` lists or matches it. Only `env.pass_secret` (exact names, no wildcards) passes a secret-looking name; `CAPSA_HUMAN` never passes. `velum self doctor` names the secret-looking variables that are set and withheld.
- `TMPDIR` is `/private/tmp/velum` and is agent-writable: nothing velum trusts may live there. srt sets `TMPDIR=/tmp/claude` itself and does not create it (swift fails without it), so `run` and `doctor` create both `/private/tmp/velum` and `/private/tmp/claude` (mode 0700, no symlink, owned by the user, else a hinted error). Generated settings, wrappers and the empty git template go in a `RunDir` under `~/Library/Application Support/velum/run/` (created with mode 0700 and exclusive create, never through a symlink, removed on drop; ones older than a day are removed at the next start). `run` refuses when an `allowWrite` entry covers it. `$TMPDIR` of the parent was rejected: `/private/var/folders` is write-allowed.
- Signals: srt runs in its own process group (the terminal's foreground group when velum has a terminal). SIGHUP, SIGTERM and SIGINT sent to velum go to that group; velum waits, then restores `~/.claude.json`, scans for git changes and removes the run directory. After the child exits, what is left of its group is killed (SIGTERM, then SIGKILL after one second) with a warning. A signal death exits with 128 plus the signal. Ctrl-Z stops the child and velum together; `fg` resumes both. This terminal hand-over is not covered by tests (needs a pty).
- `~/.claude.json` stays writable. `claude_json::Guard` snapshots the top-level `mcpServers` and, per `projects.<path>`, `mcpServers`, `allowedTools`, `enabledMcpServers`, `disabledMcpServers`, `enabledMcpjsonServers`, `disabledMcpjsonServers`, `hasTrustDialogAccepted`, `hasClaudeMdExternalIncludesApproved` and `mcpContextUris`. After the child exits it puts back only the keys that changed, merged into the file as it is then (other keys and concurrent changes stay), and warns with the key and project. The file must be a regular file of at most 16 MiB (`symlink_metadata`, opened `O_NOFOLLOW|O_NONBLOCK`, so a FIFO cannot hang velum): at the start a violation is a hinted error, after the run it is replaced by the pre-run copy through an atomic rename (or removed when it did not exist). A file that did not parse as a JSON object before the run (garbage, `[]`) is kept as bytes and put back byte for byte when it differs afterwards, deleted included.
- `settings` refuses fs entries that are not absolute after `~` expansion, contain `..`, or use `~user`; deny lists also accept `**/name`. `HOME` must be absolute; when it is a symlink, every `~` entry of the deny lists is written for both the given and the canonical path. `run` refuses a cwd that is `/`, `$HOME`, an ancestor of it, or is or lies inside `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config`, `~/.local`, `~/Library`, `~/.claude`, `~/.cargo` or `~/.rustup`.
- Git: srt's own mandatory denies always block writes to `.git/hooks` under cwd, and `.git/config` unless `filesystem.allowGitConfig` is true; velum sets it to true so `git init` works. Before the run `gitguard::Start` lists the repositories under cwd (bounded walk, no symlinks, skipping `target`, `node_modules` and `.build`; 50 000 directories or 256 git dirs at most) and adds concrete `deny_write` entries for each `.git/hooks`, `.git/config`, the `.git` file of a worktree or submodule, and the same for `.git/modules/**` git dirs and for every bare-shaped directory (`hooks`, `config`, `modules/*/hooks`, `modules/*/config`); `<cwd>/**/{target,node_modules,.build}/**/.git/config` covers the skipped directories. Past the caps, or with glob characters in a path, `<cwd>/**/.git/...` globs are added too (new repositories are then read-only and velum warns). After the child exits, a scan finds git dirs whose (device, inode) was not there before (a replaced `.git` counts), moves hook files that do not end in `.sample` to `~/Library/Application Support/velum/quarantine/<run id>/` (with the source path in the message), removes `core.hooksPath` and `core.fsmonitor` from the config of those new git dirs (a new file renamed over a regular `config`, never through a link) and warns about other entries that run code: `alias.*` starting with `!`, `credential.helper`, `core.{sshCommand,editor,pager,gitProxy,askPass}`, `gpg.*.program`, `diff.{external,*.textconv,*.command}`, `merge.*.driver`, `remote.*.{uploadpack,receivepack}`, `uploadpack.packObjectsHook`, `filter.*` and `include*`. A new `.git` file is followed only when its `gitdir:` target is inside cwd, reached without a link and absent from the start snapshot; otherwise velum warns and leaves it. A hook that cannot be renamed into the quarantine is copied only when it is a regular file; anything else is listed for removal by hand. Hooks cannot be written directly (srt), but a git dir built elsewhere and moved to `.git` gets through; the scan is for that. `GIT_TEMPLATE_DIR` is set to an empty directory in the run dir so `git init` and `git clone` copy no sample hooks, and `CARGO_CARGO_NEW_VCS=none` is set because libgit2 (cargo) ignores the template and writes `hooks/README.sample`: `cargo new` makes no repository; run `git init`.
- Trusted files: `srt` is found on the absolute `PATH` entries, then in the user bin directories of `capsa_core::which` (`~/Library/pnpm/bin` included), never through a relative entry. `run` refuses when an `allowWrite` entry covers the resolved srt; `shim install` refuses (hinted) when it covers the real claude or the velum binary and no concrete `deny_write` entry does (`~/.claude/local` is denied, so a claude there is accepted). `doctor` (check `trust`) and `shim status` warn likewise.
- The swift and xcodebuild wrappers exist because Seatbelt cannot nest. Each runs the real tool with its own sandbox turned off (`swift build`, `test` and `run` with `--disable-sandbox`; `xcodebuild` with `-IDEPackageSupportDisableManifestSandbox=1`).
- The shim is `DIR/claude` (default `~/.local/bin`): a POSIX sh script with the line `# velum shim`. It runs `exec <velum> run -- <real claude> --dangerously-skip-permissions "$@"`, with both absolute paths fixed at install time: velum is the canonical `current_exe`, claude is the first `claude` on the absolute `PATH` entries outside `DIR`. `shim status` and `doctor` warn when the baked velum no longer exists (reinstall). Install refuses a file velum did not write and a real claude that is already a shim; uninstall removes only a file with the marker.
- Claude Code floor: `velum run` refuses (hinted) a program named `claude` whose `--version` is below 2.1.163 (CVE-2026-55607); an unreadable version (or a `--version` that takes over 10 seconds) refuses too, with a hint and no override. `doctor` check `claude version` fails below the floor. The version is read outside the sandbox, so only a trusted claude should be on `PATH` (see `trust`).
- Bare repositories: the scan after a run reports new bare-repository-shaped directories (`HEAD`, `objects/`, `refs/`) under cwd; `doctor` warns unless global `safe.bareRepository` is `explicit`. Neither edits git config.
- Network: `allowLocalBinding` is never set (srt default false); `169.254.169.254` and loopback are unreachable from the sandbox. `claude.ai` and `platform.claude.com` are in the default allowlist for OAuth.
- Broker: the socket lives in the run directory (mode 0600 in a 0700 directory) and is the only unix socket srt allows (`network.allowUnixSockets`). `VELUM_BROKER` is set by `run`, not by the env allowlist, so a value inherited from outside never reaches the sandbox. If the broker cannot start, `run` warns and goes on without it. The working directory of every action is the run's, never the request's; requests with unknown fields are refused. The request is logged before anything runs, and nothing runs if the log cannot be written. `approvals.toml` and `broker.log` sit under `~/Library/Application Support/velum`, which is `deny_write` (a test in `writable.rs` covers both). Each connection has its own thread and a 30 second deadline for the request line; one request at a time may ask or run (`Handler::busy`), another gets "busy" at once. Dropping the `Broker` kills every recorded process group and open dialog (`exec::Registry`).
- Broker and git: `git_push` and `gh` act only on `repo::Recorded`, the repository around cwd at the start of the run, accepted only when `writable::writable_by` says the sandbox cannot write `common/config` and `common/hooks` (git reads them from the common directory) and, for a `.git` file (linked worktree), the file and its admin directory. A `.git` directory itself is not required to be read-only, because `gitguard` denies only its `config` and `hooks`; `verify` (path and inode) catches a replacement. Git runs with `--git-dir`/`--work-tree` of the record, `-c core.hooksPath=/dev/null -c core.fsmonitor=false`, `push --no-verify`, and, through `Executor::run(.., git_safe)`, `GIT_DIR`/`GIT_WORK_TREE` of the record, `GIT_CONFIG_COUNT` overrides of the same two keys and no other `GIT_DIR`-style variables; the system gitconfig stays. Bound commands run in the recorded root, so `gh` cannot be pointed at another repository by a `git init` below cwd. `Recorded::verify` runs before planning and again before the command. Approvals are keyed by the recorded root; `git_push` adds the push URL as subject. Only `<type>/<outcome>` branches without force may be remembered. `gh` is bound to the cwd repository; a remembered read is also bound to the origin slug (no `-S`/`--search`, `-R`/`--repo`/`--hostname`/`--web`/URLs, `api` only under `repos/<owner>/<name>` of the github.com origin, never `graphql`). Requests holding control, format or default-ignorable characters are refused (`text::forbidden`), not cleaned.
- Fail closed: every failure before or in starting srt (no srt, no run directory, no settings file, srt exit) leaves the command unstarted; there is no unsandboxed fallback.
- Errors use `capsa_core`: a policy error or a missing srt is a `Hint` error, and its fix (`velum self doctor`, `velum self setup`) renders as `hint:`, never inside the message.
- `doctor` exits 1 only when a check fails; a warning exits 0. It creates and writes `TMP_DIR` (`/private/tmp/velum`), as `run` does.

## Gotchas

- The broker checks the recorded git directory (`Recorded::verify`) before planning and again before the command; a swap in the few milliseconds between that check and git opening the directory is accepted, because `.git/config` and `.git/hooks` stay read-only throughout and a replaced directory needs a rename the sandbox cannot make there.
- srt is beta. The spike was run on 0.0.81; `velum self setup` installs it through the user's package manager (default pnpm), so the installed version can differ.
- Per-repository rules must not live inside the repository. A policy file there is writable by the agent, which could grant itself access. Per-repository sections belong in the global file.
- `~/.claude/settings.json`, `settings.local.json`, `CLAUDE.md`, `agents`, `commands`, `skills`, `plugins`, `output-styles`, `hooks` and `local`, the cwd's `.claude`, `.mcp.json`, `.gitconfig`, `.vscode`, `.idea`, `.zed` and shell init files (`.zshrc`, `.zshenv`, `.zprofile`, `.zlogin`, `.bashrc`, `.bash_profile`, `.profile`; also `<cwd>/**/name` for each), `~/.cargo/bin` and `~/.cargo/config*`, `~/.config/velum`, `~/.local/bin` (default shim dir) and `~/Library/Application Support/velum` are `deny_write`, because files there run code on the next start. `~/.claude.json` cannot be protected this way without breaking Claude Code, hence the key guard. A custom `shim --dir` is not in `deny_write`.
- srt resolves a relative `**/name` deny entry against srt's own working directory, so it works only below cwd and never for `$HOME`; velum writes anchored `<cwd>/**/name` entries instead, which `acceptance.sh` checks against a real srt (srt 0.0.80). A plain `**/.claude` would match `~/.claude` too if it were rooted at `/`: do not add one.
- Seatbelt cannot nest. Any other tool that calls `sandbox-exec` will need its own wrapper, as swift and xcodebuild have.
- velum is macOS only for now.
