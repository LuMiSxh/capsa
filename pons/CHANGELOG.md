# Changelog

## [Unreleased]

### Added

- pons records the subscription limits that the adapter forwards in rate-limit events (the five-hour and seven-day windows) in the census `snapshots` file, one line each time a window's value changes. The forwarded lines are unchanged. `--no-census` or `PONS_NO_CENSUS=1` turns it off.

## [0.7.0]

- A background subagent whose last event was a tool result, with no text since, is finished by silence only after 60 s (or `--subagent-idle-ms` when that is longer), not after the idle period, because a result is often followed by thinking. A subagent that ends with text still finishes after `--subagent-idle-ms`.

- `--mcp-server NAME=COMMAND[,ARG...]` (repeatable) adds a stdio MCP server to every `session/new`, `session/load` and `session/resume` request the client sends, so the server exists only in those sessions. A server whose name the client already sends keeps the client's entry. Each addition or skip is a wire-log note. It works when pons steps aside for native subagents.

## [0.6.0]

- Commands about pons itself are `pons self <action>`: `pons self doctor`, `pons self setup`, `pons self update`, `pons self uninstall`. `doctor` and `setup` are no longer top-level, and there are no aliases. The proxy stays the default behaviour.
- `pons self update [--check|--force]` replaces the binary with the newest published `pons-v*` release of LuMiSxh/capsa, after checking the archive against the release's SHA-256; it needs `GITHUB_TOKEN` or `gh auth login`. The new file is written beside the binary, synced and renamed over it, and a symbolic link is resolved to the real binary first. `--check` exits 0 when a newer release exists, 1 when current.
- `pons self uninstall [--dry-run]` removes the binary. Wire logs and the Zed `agent_servers` entry stay.
- `pons self setup [--package-manager pnpm|bun|npm] [--dry-run]` (with `--json`, `--human`, `--agent`): finds the Claude ACP adapter and reports its path and version, or installs `@agentclientprotocol/claude-agent-acp` globally when it is missing, with the named package manager or the first of pnpm, bun and npm found on `PATH`. `--dry-run` prints the command and installs nothing. Exits 0 when the adapter is present or installed; exits 2 with a hint when no package manager is found.
- Program lookup (`PATH`, then the user tool directories) and the install hint of `pons self doctor` now come from `capsa-core` (`which`, `pkg`). The output is unchanged.
- `pons self doctor` takes `--human` (coloured text on a terminal) and `--agent` (plain text, the default) next to `--json`, resolved like the other capsa tools. It reports whether the Claude ACP adapter can be started through the launcher: which launcher would run it, its version when known, and, when none can, the install command for pnpm, bun or npm found on `PATH`. Nothing is installed.
- The release build of pons is `cargo build -p pons --profile release-unwind`. The `release` profile sets `panic = "abort"`, which would turn the caught panics of the fail-safe into crashes.
- A top-level error is rendered by `capsa-core` on stderr as `error:` with exit code 2 (it was Rust's `Error:` line and exit 1). The agent's exit code still passes through; stdout is untouched in proxy mode.
- The per-tool install scripts are removed. pons is installed by the root `install.sh` or `install.ps1` with the `pons` argument; they read `CAPSA_INSTALL_DIR` and `CAPSA_INSTALL_SCOPE`. The README install section shows the root installers.
- `pons self setup` and `pons self doctor` find `claude-agent-acp` in the global bin directory of the package manager (pnpm, bun or npm). When that directory is not on `PATH`, the install hint names it.
- Performance: the engine parses each client line once instead of twice, and routes the same parsed value. Measured with the ignored `engine_line_cost` test (100k lines, `release-unwind`): a `session/prompt` line went from 1474 to 934 ns per line. Agent `session/update` lines take the same single parse as before (about 2.3 µs per line).
- Internal: `src/log.rs` is `src/log/` (`files.rs`, `render.rs`), `src/proxy/session.rs` and `src/engine/route.rs` hold code moved out of `proxy/mod.rs` and `engine/mod.rs`, and `tests/proxy.rs` is `tests/proxy/`, split by topic.
- pons is marked `publish = false`.

## [0.5.2]

- A SIGHUP (a closed terminal, a hangup) ended pons at once with no `exiting:` line, so the wire log just stopped. SIGHUP is now forwarded to the agent's process group like SIGTERM and SIGINT, and the log says why pons exited.
- A panic that is not caught by the fail-safe, or an error that ends pons, now logs `exiting: panic: <message>` or `exiting: error: <message>` before the process ends; a panic in a spawned task, which pons survives, logs `panic in task: <message>`. The wire log is unbuffered, so each line is already written when pons exits.
- When a subagent's child tool call starts, the wire log notes its card id, its `toolCallId`, and its title and kind (cut to 80 characters), so a stalled child can be identified.

## [0.5.1]

- A finished background subagent stayed open in Zed's plan and its finished entry never appeared. The adapter sends a periodic progress tick for the card tagged with the card itself as parent; pons tracked it as an open child tool call that nothing ever closed, so every `task-notification` found no qualifying card. Such self-parented ticks are now ignored: no tool line, no activity, no open tool.
- Integration tests no longer write logs into the real log directory (`--no-log` unless a test chooses a log path), so a test run cannot rotate away real logs.

## [0.5.0]

- Logging is on by default: each start writes its own file `pons-<YYYY-MM-DDTHH-MM-SS>-<pid>.log` in the platform log directory (`~/Library/Logs/pons/` on macOS). The newest 10 are kept; older ones matching that name are deleted at start, other files are never touched. `--log-dir DIR` changes the directory, `--no-log` turns logging off, and `--log FILE` (or `PONS_LOG`) still writes one fixed file. `pons doctor` reads the newest per-start log when no `--log` is given and accepts `--log-dir`.
- Every card reopen is logged, and a `task-notification` is matched again to an already finished card only within 30 s of its finish.

## [0.4.0]

- A message sent while subagents run no longer kills them. Zed sends `session/cancel` and, ~100 ms later, `session/prompt`; pons used to forward the cancel whenever the main agent had been active in the last `--quiet-ms`, and the adapter's interrupt stopped every background subagent. Now, with a prompt outstanding and subagents in flight, the cancel is held for `--cancel-defer-ms` (new, default 400) and the prompt is answered as cancelled at once. A prompt inside the window drops the cancel for good and is delivered with `--interrupt-mode` (new): `steer` (default when the adapter advertises `_meta.steering.supported`) sends `_session/steering` to inject the message into the running turn and answers Zed's new prompt id when the turn ends; `queue` forwards the prompt so the adapter queues it, and is the fallback when steering is unsupported, declined or fails; `cancel` is the old behavior. No prompt inside the window is a real Stop: cards are marked stopped once and the cancel is forwarded. A second cancel inside `--stop-window-ms` is forwarded at once. Without subagents a cancel is forwarded at once. The synthetic cancelled response never finishes cards. `--quiet-ms` is deprecated and ignored (a note is logged). Every branch is logged.
- Finish detection rewritten. The idle heuristic used to finish a background subagent that was only thinking or running a long tool (a real log showed three false finishes of one card, each after a tool result). Now: a prompt response finishes the background cards its prompt launched (confirmed; a response that only hands off to a newer prompt does not); a `task-notification` is attributed to a card with no open tool call, preferring one whose last event was its own text, then the quietest, and with no such card finishes nothing; silence finishes a card only when no tool call is open, the last event was the subagent's text and `--subagent-idle-ms` (default 20000) passed. Otherwise the title and roster show `quiet 1m 5s`. With `--no-subagent-text` only the new `--subagent-max-quiet-ms` (default 600000, 0 disables) can end a silent card. Silent finishes are provisional: no notice, the parent stays in flight for the cancel filter, and later activity reopens the card as a background card with its log.
- One finished entry per card: the id is `pons-finished-<parent>` (no counter). If a card reopens after its entry went out, the entry is updated (`in_progress`, `resumed`) and finally completed with the result; a second entry is never appended. Notices go only to confirmed finishes.
- Refresh ticks send title-only updates (no log re-send); `child_update` of a retired card recreates a background card instead of a foreground one.
- Resumed threads: the `[Request interrupted by user]` and `[Request interrupted by user for tool use]` user messages that Claude Code records on an interrupt and the adapter replays are dropped during the replay window of `session/load` / `session/resume` (whole trimmed text only, also when split over chunks; other text is forwarded at once, unchanged; live text is never dropped). The `replay of ... done` log line counts them. `--keep-interrupt-markers` restores the old behavior.
- Shutdown: the agent runs in its own process group (Unix). When the client closes, pons closes the agent's stdin, waits `--shutdown-grace-ms` (new, default 2000), sends SIGTERM to the group, then SIGKILL, so grandchildren no longer survive. Forwarded SIGTERM/SIGINT go to the group with a 5 s kill timer, no `sh`. On Windows the tree is ended with `taskkill /T /F`. The reason for exiting and for each prompt response that finishes cards is logged. New dependency: `libc` (Unix only).
- Fixes: `dropped_cancel` is reset on `session/prompt` (a cancel in a new prompt is no longer taken for a Stop escape); a late swallowed response no longer touches the state of a newer turn; `session/close` drops all per-session state; failures of the periodic tick are counted apart and never switch to passthrough; the swallow check stays active in passthrough; bounded memory (per-direction queues with a 32 MiB back-pressure gate and pruned maps).
- Log: the `usage_update` summary line carries `origin=<kind>`.
- Adapter workarounds (details in the README, every decision logged):
  - Turn watchdog, `--turn-stall-ms` (new, default 120000, 0 disables): a prompt that is never answered although the agent's last word was text or a `usage_update`, with no tool call, subagent or client question open and nothing received for the window, is answered `end_turn`; a late real response is dropped (adapter issues #1284, #896).
  - Ghost tool calls: when a turn ends cancelled by a real Stop, the open main-agent tool calls are closed with `tool_call_update status=failed` once, before the response (#1061). `--no-close-ghost-calls` disables it.
  - Steering hold, `--steer-hold-ms` (new, default 1500, 0 off): a steering waits for a tool call that is still streaming its input (#1267) and is queued if the old turn ends first; declined or failed steering (`promptRequired`, `noRunningTurn`, `incomplete_tool_call`, any error) still falls back to queueing.
  - Permission policy, `--auto-approve none|allow-once|allow-always` (new, default `none`) and `--auto-approve-tools LIST`: opt-in answers to `session/request_permission` for matching tools (empty list: `read`, `search`, `think`, `fetch` kinds only); plan and question requests are never answered. See the README for the security trade-off.
  - Dead adapter: outstanding prompts get a JSON-RPC error `pons: the agent process exited (code N); restart the thread` and the session one `agent_message_chunk` notice; pons exits with the agent's status. Fix: pons used to keep running after the agent died while the client held stdin open (the runtime waited for the stdin read); it now exits.
  - Checked, no change: the agent's stdout is read continuously and a client that does not read only grows the 32 MiB queue (new integration test). `<cc-memory>` tags do not exist in adapter 0.85.0, so nothing was added for them.
- `pons doctor`: labels the adapter the configured launcher resolves to apart from the Zed registry install, flags running pons processes started before the installed binary changed (`STALE`), shows log size and rotated copy, why pons last exited, provisional finishes, and has `--json`. `--help` lists every flag with its default.

## [0.3.0]

- Steps aside when the client renders subagents natively: an `initialize` request with `clientCapabilities.subagents` turns off folding, background-card rewriting, finished entries, roster, notices and the cancel filter (subagent traffic is pure passthrough) and logs one `stepping aside` note. Logging, the task-notification filter and the fail-safe stay active. `--force-features` keeps the features on.
- Fail-safe passthrough: a panic or failure in the message rules forwards the original line unchanged and logs a `fail-safe:` note; after `--max-failures` (new, default 5, 0 never) consecutive failures a session becomes pure passthrough. Panics are caught with `catch_unwind`, so the release profile changes from `panic = "abort"` to `panic = "unwind"`. A hidden `--inject-failure TEXT` (env `PONS_INJECT_FAILURE`) makes lines containing TEXT fail, for tests.
- Resumed threads: updates replayed after `session/load` or `session/resume` (before its response or the next prompt) are forwarded untouched and register no parents or background cards, so old cards are no longer closed in one burst by the idle heuristic and no entries, notices or roster come from them.
- `pons doctor [--log FILE] [--agent-cmd CMD...]`: plain-text report of version and platform, the launcher that would be used, the Zed `settings.json` agent_servers entry that runs pons (lenient JSONC), the adapter version Zed installed, and a wire log summary (cancels dropped/forwarded, stop escapes, subagents tracked/finished, fail-safe events, dropped notifications, last 5 notes). Always exits 0.
- Launcher auto-detect: without `-- <agent>` pons uses `claude-agent-acp`, else `npx -y`, `pnpm dlx` / `pnpx`, or `bunx` with `@agentclientprotocol/claude-agent-acp`, searching PATH and the common user bin directories on macOS, Linux and Windows (PATHEXT and `.cmd` shims, with arguments checked). An explicit command still wins. The Zed config no longer needs `--` or the agent path: `"command": "pons", "args": []`.
- Subagent text: the adapter forwards a subagent's text only to a client that advertises `clientCapabilities._meta["subagent-transcript"] = true` (or native `subagents`), which Zed does not, so finished entries held only `N tool calls`. pons now adds that capability to the `initialize` request it forwards (creating `clientCapabilities` / `_meta` as needed, one log note); not when it steps aside, when the client set the key, with `--no-fold`, or with the new `--no-subagent-text`. Replayed subagent text during `session/load` / `session/resume` is dropped so the capability does not flood the chat on resume.
- The `pons-finished-*` entry now carries the tool call count and the subagent's final message (last contiguous agent text, head kept, at most 2000 characters, `...` when cut); the finished card shows the same message. Running cards still show the latest 300 characters. Child text is still never forwarded flat.

## [0.2.0]

- No symbols: everything pons writes to the wire, and its docs and help, is plain ASCII. Fold lines read `running: Read src/a.rs`, `done: ...`, `failed: ...`, `agent: ...`; the final line is `done - N tool calls` (`stopped - N tool calls`, `done (no activity for 20s) - N tool calls`); entries are titled `<title> finished` / `<title> stopped`; truncation is `...`. A test asserts the synthesized output is ASCII.
- The finished entry no longer splits the main agent's text. It is queued (in finish order) and sent when the main agent has streamed no text or thought chunk for `--entry-gap-ms` (new, default 600, 0 sends at once), before the main agent's next tool call, before the prompt response that ends the turn (also a synthesized `cancelled` one), or when no prompt is outstanding. The card update itself still goes out immediately. An entry whose card reopens before it is sent is dropped.
- Earlier finish signal. The adapter's `task-notification` usage update is the only message it sends when a background subagent ends, and it comes after the follow-up turn that reports the end. pons now decides at once when it arrives (`--notify-settle-ms`, new, default 0; 0.1.2 waited a fixed 2 s for the other subagents to show activity) and releases the held entries at the same moment. In a replay of a logged session this moves the entries from 2.1 s after the marker to 0 s. The idle default stays 20 s; the logged data does not support less. Late activity still reopens a finished card.
- The raw `<task-notification>` block that Zed showed as a user message after a restart (adapters that replay it as a `user_message_chunk` during `session/load`) is dropped. A user message is held only while it can still be one (it starts with the tag, or is a prefix of it) and until the closing tag; other text passes at once, held text that is not one is released unchanged, a half-complete one after 1 s too. `--keep-task-notifications` restores the raw behavior.
- Live roster: pons keeps the adapter's latest `plan` and appends one entry per background subagent (`<title>: <last action> (N tool calls, 15s)`, `pending` / `in_progress` / `completed`), sent on change at most once a second (elapsed time refreshes every 5 s). Finished subagents stay `completed` until a turn that began after they finished ends, or 60 s. Plans without subagents pass through unchanged. `--no-roster` disables it.
- Live counters in the card title of a background subagent: `<title>: running 15s, 3 tool calls, last: Read src/a.rs`, then `<title>: done, 3 tool calls, 42s` (`stopped` after a Stop). The original description is kept for the finished entry title.
- Session notice when a background subagent finishes (`info`, `<title> finished`; `warning`, `<title> stopped` after a Stop), sent to a client that advertised `session.notices` (Zed does so only with its beta features on). `--notices` sends it regardless, `--no-notice` never.

## [0.1.2]

- Background subagent cards now finish. The adapter reports an `Agent` call completed at launch and never reports the end to Zed; pons keeps the card `in_progress` (`▸ running in the background`), keeps folding the subagent's activity, and completes it with `✓ done — N tool calls` when the adapter's `task-notification` usage update arrives (matched to the subagent that went quiet first; reopened if wrong) or, as a heuristic, after `--subagent-idle-ms` (default 20000, 0 disables) without activity. A real Stop marks running cards `failed`. Running background subagents survive the end of the launching turn and keep holding the cancel filter.
- When pons finishes a background subagent (notification, idle heuristic, or Stop), it also appends a new tool call to the thread, `✓ <title> finished` (`✗ <title> stopped` on Stop) with the tool call count and the tail of the subagent's last agent text, so the finish is noticed at the bottom instead of in the card far up. It is sent right after the card's final update. `--no-finish-entry` turns it off.
- Parent detection: besides the `Task`/`Agent` tool name (also from the top-level `name`, or title `Task` with kind `think`), any tool call that a child names in `parentToolUseId` is treated as a parent.
- `--quiet-ms` default 2000 -> 2200, from a real session: the main agent's longest gap while active was 1.9s (first token after a prompt), its quiet time before the cancel that should be held was 2.4s.

## [0.1.1]

- Stop escape: a `session/cancel` that repeats a cancel the filter dropped within `--stop-window-ms` (default 3000, 0 disables the escape) is forwarded to the agent, so the Stop button can kill runaway subagents.
- Smaller wire log: `--log-level all|default|meta` (default `default` summarizes `session/update` notifications to one line, keeping requests and responses in full; `meta` logs only pons' decisions and method names) and `--log-max-bytes` (default 5 MiB) rotating the log once to `<file>.1`.

## [0.1.0]

Initial version: transparent stdio proxy between Zed and the Claude ACP adapter with the subagent-safe cancel filter, subagent folding into the parent tool call, a wire log (`--log`, `PONS_LOG`) and SIGTERM/SIGINT forwarding. Releases ship for macOS, Linux and Windows with `install.sh` and `install.ps1`.
